Case Studies

Problems I like solving

The interesting part is rarely the API call itself — it is what happens when systems disagree or fail halfway through.

Reliability / Payments

Payment succeeds, order flow fails

Designing transaction workflows so a retry does not become a duplicate charge or duplicate order.

Patterns
Idempotency, transactional outbox, retries/backoff, reconciliation
Goal
Safe recovery from partial success across services
Inventory / Integration

Commerce ↔ POS ↔ ERP inventory consistency

Keeping stock visibility reliable when updates arrive from different systems and at different times.

Patterns
Webhooks, queues, correlation IDs, retry handling, reconciliation
Goal
Reduce mismatches and operational correction work
Performance / Data

Slow queries under production workload

Looking beyond “add another index” to the execution plan, access pattern, cache behavior and workload.

Options
Query rewrite, composite indexes, Redis, replicas, partitioning
Goal
Predictable performance as concurrency and data volume grow
Architecture / Resilience

Reducing synchronous dependency chains

Decoupling work that does not belong in the critical request path.

Patterns
Events, queues, asynchronous consumers, DLQs, observability
Goal
Fault isolation and more resilient transaction flows
